### API

The API is a small Express server in `server/` with in-memory demo data. The Expo app
reads its address from `API_BASE_URL` in `constants/api.ts` (the only place it is set).

| Endpoint | Auth | Response |
|---|---|---|
| `POST /login` `{ email, password }` | no | `200 { token, user }`, `401` wrong credentials, `400` missing fields |
| `GET /students` | Bearer token | `200 [ { id, name, email, course } ]` |
| `GET /students/{id}` | Bearer token | `200 { id, name, email, course }`, `404` if not found |
| `GET /profile` | Bearer token | `200 { id, name, email, role }` |

Protected endpoints need the header `Authorization: Bearer <token>`; a missing or unknown
token returns `401`. The token is generated by the server at login (`crypto.randomUUID()`).

Demo login: `student@example.com` / `password123` (stored only in `server/data.js`;
the app never saves the password).

### How to Run

```sh
npm install
npm run api          # terminal 1: Express API on port 3000
npx expo start       # terminal 2: Expo (press a for Android)
```

Set the API address in `constants/api.ts`: the Android emulator uses `10.0.2.2`; a physical
phone needs `USE_PHYSICAL_PHONE = true` and your PC's Wi-Fi IPv4 in `PC_LAN_IP`.

### Authentication Notes

- `context/AuthContext.tsx` holds the auth state and is the only file that calls Expo SecureStore.
- `login()` saves the token with SecureStore; `restoreSession()` reads it on startup and checks it with
  `GET /profile`; `logout()` deletes it and returns to the sign-in screen.
- SecureStore supports Android/iOS only. On web it is skipped (`isAvailableAsync()`), so a web session
  lasts until the page is reloaded.
- The API keeps tokens in memory, so restarting `npm run api` invalidates saved tokens and the app
  returns to the sign-in screen.
- Protected routes: `app/(app)/_layout.tsx` (tabs) and `app/student/[id].tsx` redirect to `/sign-in`
  when there is no token.
